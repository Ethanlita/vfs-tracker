# 保存期间的表单与资料草稿（#154）

事件提交和个人资料保存期间，使用原生 `fieldset disabled` 锁定相应表单的所有输入与按钮。锁定范围包含文本、日期、类型、复选框、社交账号增删及附件操作；用户可以阅读内容，但不能输入随后被成功响应清除的新内容。失败后恢复操作并保留提交快照，重试走原提交逻辑。

个人资料编辑期间，`userProfile` 的刷新不再回填草稿。上传头像只更新头像字段，不提交名称、公开选项和社交账号；头像成功刷新后，这些未保存内容以及待添加的社交账号继续保留。保存成功退出编辑后才同步服务端资料，取消编辑恢复最新服务端内容。账户表单也在编辑期间保留草稿、保存时锁定。编辑会话按用户 ID 隔离，切换账户时销毁旧草稿。

- 37 项资料管理与事件提交测试通过，包括头像刷新、延迟失败、全表单锁定、失败后重试及账户切换。
- 隔离生产构建通过。
- 开发/生产 × 390/1440px 四组浏览器验证通过：头像更新保留名称、公开选项和社交账号，延迟失败与延迟成功期间均锁定表单，失败后重试 body 与初次快照一致。每组恰好 5 次写请求（头像一次，资料及事件各两次）。生产手机截图已检查。使用合成账户与模拟 API，不代表真实云端部署验证。

## 范围

本修复防止同页刷新和在途输入丢失。跨页草稿、版本更新恢复、离开页面后的异步回调和账户修改部分成功分别由其他问题跟踪。依赖 #171 的逐字段更新协议，发布时必须先部署支持 `profilePatch` 的后端，再发布前端。
