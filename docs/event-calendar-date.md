# 事件日历日期

EventForm初始化和成功重置通过 `localCalendarDate` 读取当地年、月、日，避免UTC截取在凌晨或傍晚选错日期。新手动记录提交 `YYYY-MM-DD`，不再制造午夜时间戳。事件Schema明确接受日历日期和精确ISO时间戳，并关闭日期字段隐式转换，以保留原精度。

13项相关测试覆盖东八区、UTC、洛杉矶和跨月跨年，另验证手选日期提交后重置为当地当天。开发/生产浏览器分别以三个时区固定时钟，检查默认值、实际请求和重新进入的日期，6条路径通过。测试不修改系统时钟，使用合成账号和模拟API。

`parseEventDate`统一供事件详情、时间轴、管理列表、图表及相关统计读取日期。日历字符串按当地年/月/日构造；时间戳保持其瞬时语义。时间轴以“日期记录”代替未填写的具体时刻。创建/更新时间仍是时间戳。

历史边界：旧手动记录已经编码为UTC午夜，现有数据无法可靠区分它与恰好在UTC午夜发生的自动记录。本次不猜测来源、不批量改写历史时间戳。旧记录仍按时间戳展示；历史迁移若要恢复原选择日期，需要可信来源信息。新记录的日期往返不受此限制。

统一解析验证：1042项全量单元测试通过；随后补充的日期契约保真测试在11项日期测试中通过，最终生产构建通过。开发/生产×东八区/UTC/洛杉矶六条提交→列表→详情流程验证日历日期不换日，历史精确时间戳保真由独立时区测试覆盖。未部署或迁移历史数据。

视觉复核另用正常走时的浏览器，在开发/生产洛杉矶时区手选2026-09-09并重新打开详情，确认可见日期为2026/9/9。固定日期时钟会影响动画进度，因此不以冻结动画截图作为最终视觉证据。模态布局与可访问性仍由#149独立处理。
