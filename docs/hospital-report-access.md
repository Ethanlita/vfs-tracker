# 医院报告处理与访问边界

## 问题

医院检测表单曾承诺“全过程没有人工干预，不会有人看到您的报告”，但系统同时支持授权管理员在管理后台用 AWS S3 客户端生成附件限时链接。后端还会把医院报告副本上传至 Google Gemini Files API 做自动一致性审核。该承诺无法准确描述产品能力，也不足以让用户在上传前作出决定。

## 当前处理链路

1. 登录用户通过预签名上传地址把附件写入非公开 S3 桶，事件只保存对象键。
2. `autoApproveEvent` 从 S3 读取医院报告，在 Lambda 临时目录短暂落盘，然后上传至 Google Gemini Files API，与事件 `details` 做一致性比对。
3. 普通账户通过私有文件接口读取自己的附件限时链接；公共事件接口移除附件。
4. 具有相应 AWS 权限的授权管理员或运维人员可在管理后台生成附件限时链接，用于审核或故障排查。
5. 删除事件时，`deleteEvent` 先读取所属事件，删除全部可识别 S3 附件，成功后再条件删除 DynamoDB 记录。附件删除失败时保留事件供重试。

Google 官方 Files API 文档说明上传文件保存 48 小时后自动删除；Google 对 API 数据的其他处理取决于项目计费状态和适用条款，因此产品文案不对未知计费状态作额外承诺。

## 修改

上传提示现在在文件选择前明确说明默认第三方处理、授权访问、非公开范围、原文件保留方式、删除顺序和 48 小时的 Gemini 临时副本期限，并直接链接《数据保护指南》《使用协议》和 Google 官方文件说明。两份用户文档使用同一口径，移除“无人访问”的绝对承诺。

生产 SAM 模板为 `autoApproveEvent` 与 `deleteEvent` 统一注入 `ATTACHMENTS_BUCKET`，并为自动审核函数注入 SSM 中的 Gemini 密钥。删除 Lambda 删除附件失败时不再先丢失数据库记录，也不再吞掉 S3 错误。

## 验证

44 项聚焦测试通过：固定三处用户文案的关键事实，验证管理员详情确实通过独立 S3 客户端签名附件，并覆盖纯对象键、S3 URI、HTTPS 地址、跨桶拒绝、附件优先删除、S3 失败保留记录和生产模板环境变量。完整单元测试 101 个文件、1334 项通过；完整集成测试 32 个文件、623 项通过。

生产构建和性能预算通过。开发/生产 × 390/1440px 四组浏览器验收逐组检查上传页、数据保护指南和使用协议，页面异常、控制台错误与横向溢出均为零；生产手机提示区域截图已人工检查。测试使用合成账户与模拟接口，没有查看或上传真实医院报告。Google 的 48 小时期限依据其官方 Files API 文档；未推断项目的计费状态或其他数据用途。

本机 SAM CLI 1.145.1 能解析模板，但其本地规则集尚不认识模板既有的 `nodejs24.x`，因此语义校验对全部 Node.js 函数统一报运行时枚举错误；本次新增变量由静态模板测试固定。真实部署仍需由发布流水线验证。
