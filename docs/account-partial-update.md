# 账户资料部分成功恢复（#125）

账户页仍按固定顺序更新 Cognito：先保存昵称或邮箱，再修改密码。属性更新失败时立即结束，不发送改密请求；属性成功而改密失败时，`AuthContext` 返回结构化的部分成功结果，并立即读取一次 Cognito 的最新属性。

页面使用独立的琥珀色状态提示明确列出已保存字段和失败步骤，例如“昵称已保存，但密码修改失败，请检查当前密码后重试”。账户编辑保持打开，三个密码字段不清空。读回完成后再次保存时，昵称或邮箱已经与服务端一致，因此只重试密码；点击取消则使用读回结果恢复表单，不会再次显示旧昵称。如果读回也失败，最近一次已确认的界面状态和当前输入都保留，提示用户稍后重试。

资料读取同时明确区分状态：HTTP 404 是服务端确认用户不存在，会进入首次资料设置；网络错误或 5xx 无法确认用户状态，不会误开向导。Cognito 刷新失败同样保留上一次已确认信息，登出仍通过独立路径清除账户状态。
