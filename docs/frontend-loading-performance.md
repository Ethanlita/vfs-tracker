# 前端按路由加载与体积预算（#111）

公开首页只静态加载页面框架、认证状态和访客首页。公开仪表板、文档、登录、个人页面、事件管理、录音工具、图表和管理后台均使用 React `lazy` 按路由加载；认证用户进入首页时，个人时间线再单独加载。路由下载期间在原页面框架内显示带 `role="status"` 的加载状态。

`WorldJS.js` 不再由 `index.html` 全局引入。进入 VFS 效果预览后，`loadWorldJs` 才插入脚本并等待 Emscripten 运行时完成；并发调用只产生一个请求，失败后移除失败脚本并允许沿同一入口重试。RubberBand 的 WASM 仍只在实际初始化算法时导入。

Amplify UI 的样式和中文翻译只随登录路由加载。全站 Inter 字体限定为实际使用的 Latin 子集，中文继续使用系统字体。favicon 和登录页 Logo 统一使用 192×192、41,433 字节图标，页面不再请求 1.29 MB favicon 或 1.86 MB 原始 Logo。

## PWA 离线边界

公开文档、Quick F0、音阶练习、音符工具、VFS 效果预览、WORLD 和 RubberBand 资源仍进入 Workbox 预缓存，因此既有本地工具离线能力不因首屏拆包取消。没有运行时引用的 `icon.png`、`icon_origin.png` 和依赖在线 AWS 服务的管理后台代码不进入面向用户的预缓存。管理后台仍按路由下载，并使用正常 HTTP 缓存。

## 构建预算

每次 `npm run build` 完成后自动执行 `scripts/check-performance-budget.mjs`。构建在以下任一条件发生时失败：

- 初始 JavaScript 超过 900 KiB；
- 首页 CSS 超过 150 KiB；
- favicon 超过 64 KiB；
- PWA 预缓存超过 4.5 MiB；
- 首页重新直接引入 WORLD、离线工具资源漏出预缓存，或大源图/管理后台重新进入预缓存。

2026-09-11 本地生产构建结果：

| 项目 | 修复前当前分支 | 修复后 | 变化 |
|---|---:|---:|---:|
| 初始 JavaScript（解码体积） | 1,985,746 B | 822,844 B | -58.6% |
| 首页 CSS（解码体积） | 449,741 B | 135,399 B | -69.9% |
| favicon | 1,286,963 B | 41,433 B | -96.8% |
| Workbox 预缓存 | 8,537.30 KiB / 124 项 | 4,087.21 KiB / 74 项 | -52.1% |

上述是构建产物体积，不是压缩后的公网传输量。完整单元测试共 97 个文件、1,315 项，全部通过。开发与生产模式在 390×844 和 1440×900 四组真实浏览器中验证：首页和登录页没有请求 WORLD 或重量级业务路由，登录页没有请求大源图；VFS 效果预览进入后 `WorldJS.js` 与 `WorldJS.wasm` 各请求一次。四组均无页面异常、控制台错误或横向溢出。

后续引入 TanStack Query 时，状态库和 Amplify 认证库改为稳定的独立缓存块。当前业务入口为 457,586 B，Query 块为 40,071 B；首屏仍会按需加载认证和状态生命周期，但业务代码更新不会使这些依赖与入口合并成单个超预算文件。PWA 预缓存为 4,514,706 B / 75 项，仍低于原定 4.5 MiB 上限。

本地预览不能替代 `.app`、`.cn` 的 CDN 压缩、跨地域延迟、真实手机或真实用户 p75。部署后仍应沿 issue 中相同的网络与 CPU 参数重测冷/热启动、首次安装和更新，并分别收集 LCP、INP、CLS 与长任务。
