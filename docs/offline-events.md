# 离线事件队列

## 读取与恢复（#168）

快速基频测试的离线保存，以及个人页的同步入口，共用 `src/utils/pendingEvents.js`。当前存储键仍为 `pendingEvents:v1`，数据格式保持数组；读取不改写已有记录，同步准备阶段会补齐记录ID。

- 只有键不存在或成功解析为 `[]` 才表示没有记录。
- 读取权限受限、空字符串、非法 JSON 或非数组内容，均抛出 `StorageError`，不删除、不覆盖原始数据。
- 个人页显示“离线记录读取失败”，禁用同步并提供“重新读取”。权限或内容恢复后，原地重读清除错误并显示实际数量；重读不会提交事件。
- 点击同步前再次读取，避免初始化成功掩盖之后出现的权限问题。
- 收到队列更新事件、对应存储键变化或其他标签页清空存储的通知时，刷新状态。
- 数组中的单个坏条目保持原样，读取层不擅自丢弃其他有效条目。
- 快速基频离线保存同样遵守读取规则，损坏队列不能被当作空数组覆盖。

## 同步中新增保护（#104）

- 新记录包含独立的 `queueId`、`ownerUserId`、`when` 和 `eventData`，由 `pendingEventSchema` 描述。两次内容相同的测量仍是两条记录。
- `enqueuePendingEvent`、`preparePendingEvents` 和 `removeConfirmedPendingEvents` 统一通过同源 Web Locks 锁进行读—改—写。锁只包围本地存储操作，不在等待网络期间占用，允许另一个标签页继续追加。
- 开始同步前，有明确账号归属的旧条目缺少的ID先写回存储；同账号重复旧ID会区分，坏条目和无归属条目保持原样。持久化失败不开始网络提交。
- 同步结束重新读取最新队列，只移除本轮成功的ID。失败条目、坏条目和本轮开始后新增的记录均保留。
- 不支持 Web Locks 的环境明确拒绝队列写入，不使用存在竞态的无锁替代路径。只读检查仍可用。
- 本地清理失败时禁用再次同步，并提供“重试本地清理”；当前页面内保留已确认ID，重试不再次发送事件。
- Joi 校验在追加记录时动态加载，单独分包并纳入生产PWA预缓存，避免首页主包超过缓存大小限制。

验证：44项针对性测试通过，全量单元测试907项通过。生产PWA构建成功（81项预缓存）。开发/生产各验证了全成功、部分失败、清理失败重试三条浏览器路径，均使用实际同步组件和模拟接口，在第二标签页按队列锁协议追加记录；每条路径仅发送原快照的两次POST，后续记录保留，刷新后数量一致。已查看320px清理失败界面截图。此实验的第二标签页写入为模拟生产者，不能代替完整快速基频录音保存流程的端到端验收。

## 账号归属（#103，2026-09-11）

- 追加记录必须显式传入保存时的 `ownerUserId`，没有账号不允许入队。不能从缓存中的其他用户资料或当前同步账号猜测记录归属。
- 个人页计数及本次同步快照只包含当前账号的记录，其他账号的数据保持原样；清理同时核对账号和记录ID。
- 没有 `ownerUserId` 的旧记录保留在原存储中，并显示“无法确认所属账号”的提示，不自动认领或上传。需要另行设计用户确认归属的恢复流程，不能通过自动归给当前账号规避数据归属要求。
- 同步期间切换账号或离开页面，停止发送旧账号的后续记录；已经发出的请求仍使用其原始凭证，成功后仅清理对应账号的记录。
- `addEvent(eventData, { expectedUserId })` 在取得会话后，核对即将发送的 ID Token 的 `sub`，不匹配或无法确认时抛出 `AuthenticationError`，不发POST。快速基频在线保存同样传入预期账号。
- 这是客户端记录归属检查，不替代 API Gateway 对凭证的验证，不新增后端参数或改变已有事件请求体。

验证：57项针对性测试通过、全量920项单元测试和22项事件API集成测试通过，生产PWA构建成功。开发/生产浏览器验证A→B各自同步与发送前凭证变化两条路径，共4条；核对请求凭证所属账号而不输出凭证，旧记录原样保留。已查看320px旧记录提示截图。测试使用模拟账号和API，不涉及真实用户数据。

## 重试幂等（#169，2026-09-11）

- 同步请求携带 `clientRequestId=queueId`，刷新、失败重试和不同标签页都沿用原ID。
- Lambda 将认证账号与请求ID散列为稳定事件主键，并使用DynamoDB条件写入。相同账号与标识只能创建一条现存事件。
- 条件失败时使用 `ReturnValuesOnConditionCheckFailure=ALL_OLD` 返回的原记录比较业务内容，不重写审核状态和时间戳；相同内容返回原事件ID，不同内容返回409及 `IDEMPOTENCY_CONFLICT`。
- 请求标识允许1—128个字母、数字、下划线或连字符，非法值返回400及 `INVALID_CLIENT_REQUEST_ID`。未携带该字段的旧客户端仍保持原创建行为。
- 当前页面内清理失败仍只重试本地清理；刷新后允许重放同一个请求，由服务端保证不重复插入。

验证：全量936项单元测试、22项事件API集成测试及生产PWA构建通过。真实AWS SDK本地协议测试覆盖20次并发、写入后响应丢失、不同内容冲突、不同账号隔离、键顺序等价及缺少旧项时拒绝误报成功。浏览器开发/生产各验证“清理失败→刷新→重试”和“两标签页同时同步”，共4条路径，通过真实Lambda和SDK接到本地DynamoDB协议模拟器，每条路径两次POST仅一次插入。未使用真实AWS表。

## 部署顺序与边界

必须先部署 `addVoiceEvent`（包含新增的 `@aws-sdk/util-dynamodb` 依赖），验证同标识重复请求，再发布前端。旧后端会忽略新字段，不能提供幂等保证。部署不增加表或索引，仍使用现有事件表的条件PutItem；需核对现有执行角色允许请求返回条件失败的旧值。当前尚未部署、提交合入或关闭issue。

本次修复不代表整个离线流程完成。已经打开的旧版本页面不遵守新锁和账号协议，需要结合版本更新流程验收。幂等记录与事件自身共用生命周期：事件被显式删除后重放会用相同ID重新创建，不提供独立于事件永久保存的请求回执；删除后的恢复语义需要另行验收。既有无归属数据不会自动认领。
