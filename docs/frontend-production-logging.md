# 前端生产日志与认证凭据保护

## 范围

#39 的安全优先项最初来自认证初始化：`AuthContext` 会主动读取完整会话，把 ID token 字符串、解析后的 payload、邮箱和凭据存在性写入浏览器控制台。开发与生产当时都没有门禁；任何可以读取控制台、收集控制台或取得用户导出日志的代码都可能获得这份会话。

本轮删除了整条凭据诊断路径。认证状态变化不再额外调用 `fetchAuthSession`，源代码中也不再解析或打印 ID token、refresh token、AWS 临时凭据及其元数据。API 请求仍只在内存中取得 ID token 并立即交给 Amplify 请求头，业务行为不变。

## 运行时日志边界

应用运行时的 43 个源码文件已删除 273 条直接 `console` 调用，包括完整用户对象、资料、事件正文、社交账号、身份 ARN、S3 对象键、API 响应、音频样本与异常对象。认证、事件、上传、音频和管理页面继续通过原有可见错误状态、重试入口或固定安全提示反馈故障，不依赖控制台完成业务恢复。

ESLint 对 `src` 运行时代码启用 `no-console`，测试工具目录单独放行；单元测试会执行同一规则，防止后续重新引入。Vite 的所有 `build` 构建仍通过 esbuild 移除 `console` 和 `debugger`，生产 HTML 也会在模块脚本前关闭第三方依赖的控制台输出。这两层发布保护继续覆盖无法由仓库规则约束的依赖代码。

浏览器自身仍可为 HTTP 失败产生不带响应正文的网络错误条目；页面脚本不能关闭浏览器级诊断。这些条目只用于定位失败资源，不包含应用传给 `console` 的对象。

前端没有远端日志采集器，因此浏览器错误继续由页面中的可操作错误状态呈现。测试夹具的固定启动提示和合成请求诊断只在 Vitest/契约测试环境运行，不进入应用包。后端全部 Lambda 和 Python 分析链路也已完成结构化日志迁移，详见[后端结构化日志与敏感数据边界](backend-structured-logging.md)。

## 验收

- ESLint 与源码守卫要求运行时源码不含直接控制台调用；头像和待验证账号测试明确验证回退路径不会输出用户数据或损坏存储正文。
- 完整单元测试、生产 PWA 构建与性能预算在每轮修复后重新执行，最终数量以修复验收清单中的最新进度为准。
- Playwright 实际打开开发首页和公共仪表板，应用错误为 0；仅 React DevTools 提示及 React Router v7 兼容提醒来自开发依赖。公共数据请求返回 200，没有出现 `Missing Authentication Token`。
- 生产预览首页和公共仪表板的控制台消息、错误与警告均为 0。390×844 下页面根宽度与视口同为 390px，用户表格恰好挂载 20 行并显示第 1 / 8 页。
- 配置测试确认所有 Vite 发布构建移除应用 `console` 与 `debugger`，并在模块加载前关闭依赖输出；开发服务器不改变。
- 生产构建后静态检查主程序资源，确认凭据诊断标签、`tokenString` 和旧的 ID token 预览均不存在。
- 使用合成 Cognito 会话在 390px 和 1440px 执行登录、刷新和 API 失败流程，捕获生产页面全部 console 参数；两组均为零敏感标记、零页面异常。Chromium 各保留 18 条不含响应正文的 503 网络错误诊断。
- 不收集或保存真实用户 token、密码、会话和浏览器原始日志。
