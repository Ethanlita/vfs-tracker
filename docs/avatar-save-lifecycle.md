# 头像保存状态（#102）

头像操作依次执行图片读取与解码、上传、获取访问地址、资料保存。SecureFileUpload等待onFileUpdate返回的Promise，AvatarUpload返回父组件保存Promise，UserProfileManager将保存失败传回上传组件统一显示错误与重试。

成功前始终显示已确认的currentFileUrl，不将本地Data URL当成当前头像。忙碌状态覆盖图片解码和资料保存，期间禁用文件输入并阻止再次选择。损坏图片在申请上传地址前拒绝。失败后旧头像保留；重试复用已成功上传的对象，不重复PUT文件。

头像资料保存失败仅在上传组件展示一个错误入口，避免父子组件重复提示。资料保存和刷新完成后更新头像与成功反馈。文件选择取消不影响旧头像。

59项上传/资料集成测试和生产构建通过，包含解码失败、延迟保存、父级拒绝、旧头像保留、重试不重复PUT及成功接收新currentFileUrl。浏览器证据位于output/playwright/frontend-audit/avatar-save-browser.log，使用合成账户与模拟API。

开发/生产、390/1440px四组浏览器验证通过：损坏PNG零上传；有效PNG上传一次，资料保存首次模拟400、重试成功共两次；慢保存期间输入禁用且旧图不变，失败保持旧图。成功后当前DOM内三处导航头像及资料头像均使用同一新地址，刷新后资料头像仍一致。已查看生产手机失败截图，旧头像及唯一重试入口清晰。此处刷新一致性基于模拟服务保存结果，不代表真实云端持久化验收。

本项不覆盖#171所述头像与其他资料同时写入完整快照造成的覆盖问题，也不表示所有账号切换/页面离开竞态均已解决。尚未提交或部署。
