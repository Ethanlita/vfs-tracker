# 用户资料服务器状态

用户资料由 TanStack Query 统一读取、校验、缓存和更新。`AuthContext` 仍向页面提供 `userProfile`、`profileLoading`、`needsProfileSetup` 与保存方法，但不再维护第二份 React state，也不再手写账号资料的 `localStorage` 读写。

## 唯一查询路径

- 查询键固定为 `['profile', userId]`，登录账号是缓存隔离边界。
- `GET /user/{userId}` 的响应进入缓存前必须通过 `profileQueryResponseSchema`，并且响应 `userId` 必须等于查询账号。
- 登录恢复后由 `useQuery` 启用查询。Provider 会先恢复持久化状态，再决定是否请求，避免恢复与网络读取互相覆盖。
- 资料在 60 秒内视为新鲜；过期、窗口重新获得焦点或重新联网时按同一路径刷新。
- 成功资料最多持久化 24 小时。失败响应、Mutation 与其他未明确标记的查询不会写入持久化存储。

持久化容器使用 `vfs-tracker:server-state:v1`。旧的 `userProfile:v1:<userId>` 和全局资料缓存不再读取；保留旧键只会造成两套状态来源，因此不会作为回退路径。

## 保存与失效

资料设置和资料编辑都通过 TanStack Query Mutation 执行。服务器返回的完整 `user` 会先经过同一 Schema 与账号归属校验，再写入 `['profile', userId]`。所有消费者会立即观察到写请求确认的数据；缓存同时标记为失效，下一次正常刷新再向服务器校验，不会在保存后追加第二次 GET 覆盖新结果。

`PUT /user/{userId}` 的响应契约是 `{ message, user }`。前端 Schema 与 Lambda 的实际响应保持一致。

## 离线和账号切换

刷新或重新挂载时，新鲜的持久化资料可以直接恢复；离线查询暂停时页面仍显示已校验缓存，也不会把临时网络失败误判成首次资料设置。没有缓存且服务器明确返回 404 时才进入资料向导。

切换账号后，组件只订阅新账号的查询键，因此不会显示上一账号的资料。登出会同时删除内存中的全部资料查询和持久化容器，节流写入即使随后保存空状态也不会包含原账号数据。

## 验证范围

单元测试覆盖查询键、缓存时效、响应 Schema 与账号归属拒绝。AuthContext 集成测试覆盖首次读取、持久化重挂载不重复请求、离线可见数据、账号隔离、404 引导、保存后立即更新且不追加 GET，以及登出清理。资料组件测试验证普通保存和头像保存都只通过统一状态入口更新页面。

生产构建把 TanStack Query 与 Amplify 认证依赖拆成稳定缓存块。2026-09-11 的最终构建入口为 457,586 B，Query 块为 40,071 B，PWA 预缓存为 4,514,706 B / 75 项，均通过既有预算；没有提高预算阈值。
持久化恢复测试通过 TanStack Query 的公开持久化 API 显式写入并等待完成，再重新挂载应用验证新鲜缓存与零重复请求；测试不依赖节流计时器猜测缓存何时落盘。
