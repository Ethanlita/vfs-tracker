# 统一路由访问控制（#35）

主站路由统一由 `src/routes/RouteAccessGuard.jsx` 判断访问权限。守卫只读取 `AuthContext` 暴露的认证状态，不再由 `App.jsx` 同时读取 Amplify 状态并通过多个 `useEffect` 竞争跳转。

## 路由规则

| 路由组 | 登录要求 | 资料不完整时的行为 |
| --- | --- | --- |
| 首页、公共仪表板、文档与未知地址 | 无 | 在线时进入资料向导 |
| 基频、音阶、音符换算、VFS 效果预览、登录页 | 无 | 保留当前页面 |
| 我的页面、事件、资料管理、嗓音测试、API 测试 | 有 | 在线时进入资料向导 |
| 资料向导 | 有 | 保留当前页面 |

认证尚未初始化，或 Amplify 已确认会话但 `AuthContext` 仍在恢复账号时，守卫显示加载状态。它不会先把用户送到登录页再跳回。未登录用户进入受保护路由时，完整路径、查询参数和锚点会写入经过校验的 `returnUrl`。

资料引导只在在线、资料读取完成、确实缺少资料且没有待同步离线草稿时启动。离线期间保留当前页面；恢复联网后，仍由同一个守卫重新判断。需要允许资料不完整的新页面必须显式挂到 `allowIncompleteProfile` 路由组，受保护页面同时声明 `requiresAuth`。

## 验证

`tests/unit/routes/RouteAccessGuard.test.jsx` 覆盖认证初始化、会话恢复、未登录返回、正常放行、资料引导、显式例外、待同步草稿和离线恢复八种路径。`tests/integration/components/App.test.jsx` 继续覆盖真实页面路由与加载边界。
