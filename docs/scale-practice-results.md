# 音阶练习结果与结束行为

> 节拍速度、基频采样与整句判定的说明见 [音阶练习：速度、检测与整句判定](scale-practice-tempo-and-evaluation.md)。

结果只包含检测通过轮次的边界。起始音和分析器参考最低频率不用于补齐未测结果；手动“强制通过”只推进练习，不改变已测音域。尚无通过轮次时显示“未测得”。

中途结束和下降失败后的结束共用 `handleEndPractice`，调用 `cleanupAudio` 停止音轨、关闭上下文并取消采样与轮次调度。推荐请求必须同时有有效最低和最高边界，且最低不高于最高；按钮与请求处理均检查该条件。

结果页隐藏旧麦克风电平和音色提示，显示“练习已结束，麦克风已关闭。”，避免将最后一帧电平误当成实时采集。

新增 `ScalePractice.results.test.jsx` 的8项组件测试覆盖直接结束、首轮失败、跳过、下降结束、保留已通过上行、保留完整上下界、演示不计结果与练习中离开。测量算法由独立测试覆盖；组件测试隔离检测结论以验证消费结果的流程。

音频初始化带生命周期标识：离开或清理使旧请求失效，迟到授权立即停止自己的音轨，迟到音色成功/失败不再启动采集。模块音色缓存已移除，音色仅保留在其所属的组件上下文内。初始化失败清理已获准的音轨。12项组件测试覆盖上述路径，生产构建及开发/生产迟到授权浏览器测试通过。

单拍、提示音、校准等待与耳机检测采样统一由 `createAudioTasks` 管理。清理音频时同时取消会话任务：等待返回false、采样返回null，调用方立即退出；已取消会话不能新建等待。递归轮次计时器和音高/进度动画帧继续由原有清理路径释放。

18项音阶组件测试覆盖结果来源、结束、迟到授权/音色、初始化失败及各等待阶段离开；3项任务工具测试验证正常返回、取消清理和读取异常。取消并不是暂停，用户重新进入需要新的音频会话。真机兼容性和声学准确性不在这些合成输入测试的证明范围内。

## 再来一次

结果页按钮为「返回 / 再来一次 / 获取歌曲推荐」。点「再来一次」后，页面短暂显示"正在重新打开麦克风…"，然后直接进入设置页，跳过权限说明、环境噪声与耳机检测、起始音校准。

- **沿用**：环境噪声基线、起始音（包括在设置页手动调过的值）、所选模式、速度、麦克风软件增益。
- **清空**：最高音、最低音、歌曲推荐与错误提示、诊断面板的"上一轮判定"。
- **麦克风**：结果页已经关闭麦克风，所以「再来一次」会重新申请。它和权限页共用同一个函数 `openAudioSession`：清理旧会话 → 新建等待/采样任务 → 申请麦克风并建立分析链路。浏览器是否再次弹出确认框由浏览器决定：Chrome 已授权时不会再问；选过"仅这次允许"或使用 Safari、Firefox 时可能再问一次。
- **失败**：申请被拒或设备不可用时，转到权限页显示错误，用户从"重新尝试获取权限"走完整流程。
- **增益**：新建链路时直接把当前软件增益写入 GainNode。原先固定写入 0 dB，只在拖动滑块时同步，重建链路后滑块显示会与实际增益不一致。
- 获取歌曲推荐的请求进行中时，「再来一次」按钮禁用。

沿用的噪声基线是第一次进入时测的。如果中途换到更吵的环境，可以返回首页重新进入，走一遍完整流程。

`ScalePractice.results.test.jsx` 新增3项组件测试：直接回到设置页且结果清空、起始音与增益沿用（新会话的 GainNode 为当前设置值）；申请失败转到权限页并可重新走完整流程；等待授权时离开，迟到音轨被关闭且不创建新上下文。合成歌手 e2e 测试补充"练完 → 再来一次 → 再练一轮通过"，2026-11-07 在开发模式 Chromium 与生产构建（桌面、Pixel 5）上通过，并检查了结果页按钮截图。真实麦克风的重复授权行为未在自动化测试中覆盖。
