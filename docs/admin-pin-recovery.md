# 管理员 PIN 解锁故障恢复

管理员凭证仍使用 Web Crypto API 的 PBKDF2 与 AES-256-GCM 加密，并只保存在当前浏览器的 `localStorage`。PIN 解锁现在把本地解密与 AWS STS 验证分成明确结果，临时连接故障不会再被当成凭证失效。

## 用户可见行为

- PIN 错误或 AES-GCM 认证失败时保留原始密文，用户可以重新输入 PIN。由于 AES-GCM 的认证失败本身不能区分错误 PIN 与密文被修改，提示会同时说明这两种可能。
- 断网、超时、限流、AWS 5xx 和未识别异常均显示可重试的连接错误，并保留密文。恢复后可直接使用同一个 PIN 再次解锁。
- STS 明确返回 `InvalidClientTokenId`、`SignatureDoesNotMatch`、`InvalidSignatureException`、`UnrecognizedClientException` 或令牌过期时，页面说明 AWS 已拒绝凭证，清除无效密文并切换到 Access Key 登录。
- JSON、字段或解密后内容损坏时，页面明确提示本地记录损坏，清除不可用记录并切换到 Access Key 登录。不受当前页面支持的未来存储版本会保留，避免旧版本页面破坏新格式。
- 用户点击“使用其他凭证登录”时，通过上下文中的唯一清理入口同步删除存储和更新页面状态。

初次勾选“记住凭证”登录时，应用会等待加密写入完成，之后才发布认证状态并导航。这样立即刷新不会中断尚未完成的 PBKDF2 与 `localStorage` 写入。管理路由的加载状态也统一使用上下文实际提供的 `isLoading` 字段。

## 验证

聚焦测试共 15 项，覆盖真实 Web Crypto 加密往返、错误 PIN、损坏 JSON、未来版本、断网、超时、503、恢复成功、三种 STS 明确拒绝、主动清理，以及延迟加密写入期间不得提前认证。完整单元测试 104 个文件、1351 项通过；完整集成测试 32 个文件、630 项通过；生产构建及性能预算通过。

浏览器验收覆盖开发与生产构建、390px 与 1440px 四组。每组均从登录表单实际生成加密记录，随后验证错误 PIN 不请求 STS，断网和超时各经历三次 SDK 请求后仍保留密文，联网后原 PIN 解锁成功；明确拒绝和损坏存储则清除记录并同步切换页面。四组均无页面异常或横向溢出，手机与桌面错误状态截图已检查。AWS 请求全部由浏览器拦截并使用合成身份，没有发送真实 IAM 凭证或执行真实云端操作。
