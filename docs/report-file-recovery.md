# 报告文件访问与局部恢复（#161）

附件解析工具仅接受服务返回的HTTP(S)绝对地址，空响应、原始对象key和其他协议均视为失败。单文件函数传播错误；批量函数保留失败文件元数据，返回空downloadUrl及downloadError，不再把对象key伪装成浏览器链接。EventList既有错误提示路径已通过回归。

TestResultsDisplay立即显示指标，图表和PDF使用独立ReportFile组件加载。失败显示文件级提示及重试按钮，无破图或对象key下载入口。单项重试只请求该文件，同步锁阻止重复点击；切换报告后旧响应不能覆盖新文件。图片加载失败（含过期链接导致的资源错误）转入重试状态；PDF提供刷新链接按钮，用户可重新获取过期访问地址，不代表已自动检测PDF阅读器中的所有下载错误。

## 验证

55项附件/报告测试、51项EventList调用方测试及隔离生产构建通过。错误测试涵盖400/403/404/500/断网、空/非法地址、旧响应、图片失败及重复重试。

开发3110/生产3111、390/1440px共4组浏览器流程通过。每组通过实际录音控件完成12段合成音轨，用模拟分析结果生成报告。链接等待时指标可读；图表与PDF模拟400后都显示局部错误。分别重试仅增加两次file-url，不增加录音上传、analyze或results请求；图表解码成功，PDF链接恢复为合法访问地址。未修改真实账号、文件或分析结果，不用于音频算法有效性结论。

证据：output/playwright/frontend-audit/report-file-tests.log、report-file-consumer-tests.log、report-file-browser.log、report-file-3111-390.png。

## 上传后链接恢复（追加验证）

SecureFileUpload保留成功PUT的File与对象key，链接失败明确提示“文件已上传”，重试只请求访问地址。重新选择文件或放弃时清除这一阶段记录。头像和普通附件共用地址校验，非法地址不能触发完成回调。

64项上传/工具/表单测试通过，包含头像与附件重试、空地址及对象key。双模式390/1440px四组浏览器验证403/404/500/断网→非法地址→有效地址：每组始终一次上传地址请求和一次PUT，恢复后才加入一个附件。500/断网由SDK自动重试，因此链接总请求为5次，403/404为3次。证据为upload-link-recovery-tests.log和upload-link-recovery-browser.log。

所有改动尚未提交或部署。

最终复核：全量1118项单元测试通过；将表单总提示统一为“附件尚未就绪”后，9项表单测试、最终生产构建及生产手机单组链接恢复复验通过。
