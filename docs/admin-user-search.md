# 管理用户跨页搜索（#115）

管理员用户列表现在通过统一的 `searchUsers` 服务入口加载普通列表和搜索结果。无搜索词时按 DynamoDB 真实游标每次加载 20 人；有搜索词时按游标继续扫描，某一页没有匹配项也不会提前显示零结果，直到收集满 20 个匹配用户或扫描完整张表。

搜索对用户 ID、邮箱、`profile.name` 和 `profile.nickname` 执行大小写不敏感的包含匹配。每批结果保留最后一次扫描返回的真实 `LastEvaluatedKey`，所以搜索结果也能继续分页，不再生成无法恢复扫描位置的伪游标。搜索词写入 `q` 查询参数，清除、刷新和浏览器历史导航使用同一已应用查询状态；新查询会立即使旧列表与旧分页请求失效。

列表标题在还有游标时显示“已加载 N 个用户”或“已加载 N 个匹配用户”，只有扫描结束后才显示“共 N 个用户”或“共找到 N 个用户”，避免把首批数量冒充总数。

新增 7 项服务测试和 2 项页面测试，覆盖普通分页、后续页 ID/邮箱/姓名/昵称目标、真实搜索游标、后续扫描失败、搜索结果追加、完整零结果和清除恢复。管理读取重试的 5 项回归也通过；稳定化异步用户详情视觉快照后，完整单元测试共 88 个文件、1260 项全部通过，隔离生产构建通过。开发/生产 × 390/1440px 四组 Chromium 验收每组执行 15 次用户扫描，核对三类后续页目标、21 条搜索分页及完整零结果；生产手机和桌面截图已检查。
