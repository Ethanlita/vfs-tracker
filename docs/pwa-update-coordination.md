# PWA 跨标签页更新协调

## 问题

`vite-plugin-pwa` 在新 Service Worker 激活后会让所有受控标签页重新加载。旧实现只在点击“立即刷新”的标签页里征求同意，因此另一个已经选择“稍后提醒”的标签页仍可能被刷新，并丢失只存在于 React 内存里的事件表单、录音或向导进度。

## 更新协议

页面通过 `BroadcastChannel` 的 `vfs-pwa-update-coordinator:v1` 频道共享工作状态。频道只传输固定的工作类型名称和随机标签页标识，不传输表单字段、账号信息、音频或附件内容。

用户点击“立即刷新”后，当前标签页先广播探测请求，并在短暂探测窗口内收集所有标签页的阻止项。只要任一标签页仍有未完成工作，等待中的 Service Worker 就不会激活，横幅会列出需要先保存、完成或放弃的工作。所有标签页都安全后，应用才调用现有的 `updateSW(true)`；Service Worker 随后按同一条既有路径激活并让受控标签页切换到同一版本，避免新旧资源混用。

当前登记的阻止项包括：

- 新增事件表单及附件处理
- 文件或头像上传
- 录音任务与嗓音测试向导
- 个人资料编辑与首次资料设置
- 快速基频测试与音阶练习

浏览器不支持 `BroadcastChannel` 时，应用不会在页面内直接激活更新，而是提示用户关闭本站其他标签页后重新打开应用。更新注册或 Service Worker 通信失败时，横幅恢复可操作状态并允许重试。

## 生命周期边界

协调器只能保护已经加载这版代码的标签页。用户从更旧版本首次升级到包含本修复的版本时，旧页面仍按旧逻辑运行，无法由新版本反向加入协调；安装过本版本后，后续版本更新才具备完整的跨标签页保护。

阻止项保护的是当前页面中尚未持久化的工作。已经存入 `pendingEvents:v1` 的离线事件继续由离线队列协议负责；更新协调器不会复制、修改或清理该队列。

## 验证

158 项相关测试及完整 94 个文件/1301 项单元测试通过。单元和组件测试覆盖本标签页阻止、远端标签页阻止、探测期间新增工作、无阻止项时只激活一次、不支持频道、组件卸载清理，以及横幅的阻止与失败重试状态。最新生产 PWA 构建成功，预缓存包含 95 项资源。

生产 PWA 端到端验收使用两个内容不同且都有真实 Service Worker 的构建版本，在 390px 和 1440px 的 Chromium 中分别执行：

1. 版本 A 的事件页保留未提交草稿及一条持久化离线队列记录。
2. 第二个标签页下载版本 B，并尝试立即刷新。
3. 核对版本 B 保持 waiting、事件页没有导航、草稿和离线队列完全不变。
4. 保存事件后再次更新，核对两个标签页都受版本 B 控制、waiting worker 消失、离线队列仍完全不变。

两种宽度均只有一次事件写请求，没有资源 404 或页面异常。测试使用合成账号和本地拦截接口，没有写入真实 Cognito、API Gateway、DynamoDB 或 S3。
