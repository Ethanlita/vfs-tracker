# 限速配置校验（#118）

四项配置使用同一组有限整数规则：时间窗口为 1–168 小时，最大请求次数为 1–100。管理页保留用户输入的空值、小数和越界文本，提交时在对应字段显示中文错误、标记无效并聚焦第一个错误；非法值不会调用 SSM 写入。SSM 服务层再次校验，程序调用也不能绕过页面保护。

两个实际部署的 Lambda 限速器在缓存 SSM 配置前执行同样的整数与边界校验。非法远端配置会留下明确的 CloudWatch 错误并使用既有安全默认配置，不会直接参与普通用户的限速判定。`checkRateLimit` 和历史清理函数也做防御校验，因此即使请求历史为空，负数或零上限也不会被解释成“用户已经超限”。两个部署目录继续由一致性测试防止代码漂移；`lambda-functions/shared` 中的维护副本同步了相同规则。

87 项页面、SSM 服务、Lambda 纯函数及副本一致性测试通过，覆盖负数、零、空值、小数、超限、非有限值及全部合法边界。隔离生产构建通过。开发/生产 × 390/1440px 四组浏览器检查逐项输入空值、-5、0、1.5、101，均保留原值、显示字段错误且产生 0 次写入；随后保存 168/100/1/1 四个合法边界值，每组恰好产生 4 次写入且字符串值未被改写。手机和桌面错误状态截图已检查。

该规则修复数值有效性。多参数部分保存与服务端状态重新核对由 #119 单独处理。
