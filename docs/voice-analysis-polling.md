# 嗓音报告查询（#108）

`useVoiceAnalysis`区分分析提交、结果查询和用户确认的重新计算。生成报告的同步操作标识阻止重复提交；读取失败的“继续查询结果”只查询现有会话，不重新POST分析。即使提交响应丢失，也先提供查询原任务状态的入口。任务明确失败或用户确实希望重新计算时，仍需通过“重试分析/重新生成报告”的确认，再点击生成。

查询采用请求结束后安排下一次`setTimeout`，正常间隔3秒。401/403等不可自动恢复错误直接显示读取错误；网络异常、408、429和5xx连续失败时等待6秒、12秒再查询，第三次失败转为手动恢复。一次等待最多10分钟，包括离线时间；到期取消当前查询并允许用户显式继续查询原任务。此期限约束本地等待，不代表撤销服务端任务。

离线事件取消在途GET并清除下次计时，显示查询已暂停；联网后自动继续原会话。会话变化、重置或卸载会使操作身份失效，清理定时器并取消GET，旧响应不能修改新状态。分析POST已经送到服务器后无法由这个前端取消；迟到的提交响应不会在离开后启动轮询。

结果查询的`AbortSignal`由API层接入Amplify操作的`cancel`，超时也取消底层GET，而不只是停止等待其Promise。认证获取完成后检查已取消信号，防止迟到认证再发请求。

## 验证与边界

12项hook测试覆盖慢查询不重叠、重复生成、401/403只重查、404/410会话过期、429/500有限退避、离线取消与恢复、旧会话响应、提交等待时卸载、10分钟期限和任务失败区分。3项API测试验证底层取消、取消后不发请求及超时取消。#108 完成时全量51个文件、981项单元测试通过，原有35项向导集成测试通过，生产PWA构建成功；#109 恢复流程加入后，最新完整结果见[嗓音测试刷新恢复](voice-test-recovery.md)。

开发/生产浏览器各完整走过12段合成录音及问卷跳过步骤，进入报告页。首个GET延迟6.5秒后返回401，最大查询并发为1；点击“继续查询结果”后分析POST仍为1。真实断网4秒无新GET，联网后恢复原任务并进入完成状态。随后明确确认重新生成，POST才增至2；再次查询等待时离开页面，观察到请求取消且没有后续轮询。两种模式均共4次GET、1次客户端取消。已检查320px读取错误截图。录音上传及分析接口均隔离拦截，没有执行真实云端分析；模拟完成结果只用于状态机验证，不用于检验报告指标质量。

测试使用隔离会话，不验证服务端分析任务本身的幂等性。#109 已在后续改动中加入刷新恢复与原任务续查，详见[嗓音测试刷新恢复](voice-test-recovery.md)。代码尚未提交或部署。
