# 管理用户详情的异步归属（#173、#174）

权限保存按目标 userId 记录同步请求锁、忙碌状态、确认值和错误。A 的请求在途时可以关闭、重开或查看 B；重开 A 仍保持保存锁，B 可以独立操作。成功只将 `{userId, isAdmin}` 回传父页面；用户列表按 ID 合并字段，只有仍选中同一用户时才更新详情，迟到成功不能重新选择用户。失败保留原确认值并提供重试入口，错误不会显示在另一用户的详情中。离开列表后不再回调父页面。

最近事件按用户 ID 记录加载、成功与错误状态，切换时不展示旧用户内容。关闭或切换使旧查询失效，旧成功和旧失败都不能更新新请求的状态。失败明确显示“最近事件加载失败”及原地重试；只有查询成功且结果为空才显示“暂无事件”。最近事件计数也只在成功后出现。

头像独立加载，结果同时核对用户 ID 和对象 key；迟到图片不覆盖新用户，头像请求不阻塞事件展示。抽屉尚未选中用户时不请求资料，保持正常的关闭状态。

## 验证

11 项抽屉测试通过，包括空抽屉、保存成功/失败后切换、关闭重开、卸载后回调、事件旧成功/旧失败、加载错误重试及头像迟到。生产构建通过。开发/生产 × 390/1440px 四组浏览器检查均完成 6 个场景，每组核对 5 次权限写入和 17 次事件查询；错误区手机和桌面截图已检查。最新完整单元测试为 79 个文件、1176 项全部通过。所有管理操作验收使用合成 AWS 凭据及拦截服务，不改变真实管理员权限或医疗记录。
