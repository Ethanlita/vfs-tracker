# 离线资料设置与冲突保护

资料向导在离线时把“完成设置”或“跳过设置”保存为当前账号独立的浏览器草稿。草稿写入成功后页面才会离开；浏览器拒绝存储时保留表单并显示错误。回到向导会恢复完整资料草稿，个人页会显示待同步状态和手动重试入口。

## 本地草稿

每个账号使用 `pendingProfileSetup:v2:<encoded userId>`，内容包含 UUID 草稿 ID、所属账号、互斥的完整/跳过 payload、保存时间、返回地址，以及保存时看到的服务端版本：

```json
{
  "version": 2,
  "draftId": "00000000-0000-4000-8000-000000000105",
  "ownerUserId": "us-east-1:example",
  "payload": {
    "profile": {
      "name": "示例昵称",
      "bio": "",
      "isNamePublic": false,
      "socials": [],
      "areSocialsPublic": false
    }
  },
  "baseVersion": {
    "exists": true,
    "updatedAt": "2026-09-11T00:00:00.000Z"
  },
  "kind": "complete",
  "savedAt": 1789084800000,
  "returnUrl": "/mypage"
}
```

浏览器用 Web Locks 串行化同账号的保存和清理。服务器确认后只按 `draftId` 删除刚同步的版本；另一个标签页后来保存的草稿不会被旧请求清除。旧的 `pendingProfileSetup:v1` 只有在 `userId` 属于当前账号时才迁移，迁移后因缺少可靠服务端版本必须由用户明确确认覆盖。

## 同步流程

1. 登录或本地草稿变化时只读取当前账号的键。
2. 在线且没有已知错误或冲突时自动调用 `POST /user/profile-setup`。
3. 后端强一致读取 `VoiceFemUsers`，比较 `baseVersion`，并通过条件 Put/Update 再次检查版本后写入。
4. 成功响应后客户端把已校验用户写入 `['profile', userId]` 的 TanStack Query 缓存，再按草稿 ID 清理本地记录。
5. 网络或存储失败保留草稿并提供重试。409 冲突会停止自动同步。
6. 用户选择“使用离线草稿覆盖”时，客户端先读取最新服务端资料，使用它的版本重新提交；该操作只覆盖向导拥有的资料字段，保留头像等其他字段。

账号切换不会扫描或提交其他账号的草稿。完整设置和跳过设置使用同一个严格 schema：完整设置必须包含五个资料字段，跳过设置只能包含 `setupSkipped: true`。

普通资料读取和已确认资料的离线恢复统一遵循[用户资料服务器状态](profile-server-state.md)；本页的浏览器草稿只保存尚未由服务器确认的首次设置意图。

## 发布顺序

先部署 `vfsTrackerUserProfileSetup` Lambda，再发布前端。新后端要求 `baseVersion` 并拒绝旧请求；新前端也会在发送前校验协议。这个顺序确保离线草稿的版本保护在界面开始自动同步之前已经生效。

## 验证范围

117 项相关单元和集成测试覆盖账号隔离、旧草稿迁移、跨标签页草稿 ID 清理、存储失败、完整/跳过协议、联网自动同步、409 停止和明确覆盖，以及 Lambda 的强一致读取和条件写入。完整单元测试共 92 个文件、1295 项，生产构建通过。

浏览器验收已在开发服务器和生产构建的 390px、1440px 四种组合下通过。每组都验证了离线草稿刷新恢复、恢复联网后的版本冲突、草稿保留、读取最新版本后明确覆盖、其他账号草稿不受影响、最终资料可见，以及存储失败时不离开向导。测试使用合成的 Cognito 身份和 API 响应，没有写入真实账号或云端数据；浏览器共观察到两次资料请求，分别携带保存草稿时的旧版本和用户确认覆盖前读取到的新版本。
