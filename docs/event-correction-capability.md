# 事件纠错能力说明（#148）

当前用户事件接口只提供创建、读取和删除，没有定义更新事件、重新审核状态或附件替换的协议。因此事件管理页不再承诺不存在的编辑能力，并在列表说明与事件详情中统一提示：已保存事件不能直接编辑；需要纠正时，删除原记录后重新新增。

该规则适用于所有事件类型以及 `pending`、`approved`、`rejected` 三种状态。页面保留详情查看和删除入口，详情底部的说明与操作按钮允许在窄屏换行。原本未被 `EventManager` 使用的更新回调已经删除，避免继续暗示第二条更新路径。

如果以后增加事件更新，必须先定义所有者校验、可修改字段、附件生命周期和修改后的审核状态，再同时加入 Lambda、SAM 路由、前端 API、数据契约及真实环境契约测试；在此之前不应只增加前端编辑表单。

## 验证

- `EventManager` 与 `EventManagerPage` 两个完整集成测试文件共 37 项通过，其中 6 项逐一覆盖所有事件类型并组合 `pending`、`approved`、`rejected` 三种审核状态；删除、分页和日期范围另有 13 项单元回归通过。
- 生产构建及前端资源预算通过。
- 开发与生产构建分别在 390×844 和 1440×900 验证，共四组；每组打开六种事件详情，均显示统一纠错说明且没有编辑按钮。页面异常、控制台错误和横向溢出均为零。
- 浏览器使用隔离合成账号和模拟 API，没有读取或删除真实事件。
